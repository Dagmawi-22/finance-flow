# FinanceFlow

FinanceFlow is a wallet and ledger platform focused on reliable money movement, transaction consistency, and accounting traceability.

Balances are maintained as a materialized projection of completed ledger entries, with reconciliation support to verify the projection against ledger history.

## Problem Statement

Simple wallet apps that update balances directly are hard to audit, reconcile, and recover. FinanceFlow records every deposit, withdrawal, and transfer as ledger entries and keeps wallet balances in sync with that history.

## Implemented Features

* User registration with automatic wallet provisioning
* Deposits, withdrawals, and wallet-to-wallet transfers
* Double-entry ledger posting (including system settlement account)
* Materialized wallet balance updated on each ledger post
* Ledger-based balance reconciliation
* Transaction history per wallet
* Idempotent money operations via `Idempotency-Key` header (Redis + PostgreSQL)
* JWT authentication and wallet ownership checks
* Configurable per-transaction and daily outgoing limits
* Wallet status enforcement (ACTIVE required for operations)

## Architecture

* Spring Boot API with PostgreSQL persistence
* Redis for idempotency locks and response caching
* Flyway migrations
* Integration tests with Testcontainers
* GitHub Actions CI

## Financial Model

* Amounts are stored as integers in minor units (e.g. cents)
* User wallets cannot go negative
* Deposits credit the user wallet and debit a system settlement wallet
* Withdrawals debit the user wallet and credit the system settlement wallet
* Transfers debit the sender and credit the receiver
* Each completed transaction must balance debits and credits

## API Overview

* `POST /api/v1/users` — register
* `POST /api/v1/auth/login` — JWT
* `GET /api/v1/wallets/{id}` — balance
* `GET /api/v1/wallets/{id}/transactions` — history
* `POST /api/v1/wallets/{id}/deposits` — deposit
* `POST /api/v1/wallets/{id}/withdrawals` — withdraw
* `POST /api/v1/wallets/transfers` — transfer

Optional request fields: `reference`, `metadata`. Optional header: `Idempotency-Key`.
